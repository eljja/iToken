## 🤝 Core Agreements & Gap Resolutions (5 Gaps)

### 1. Terminology Stabilization (Gap 1 Resolved)
*   **iToken (Native Coin):** The sovereign ledger currency (cryptocurrency) of the iToken blockchain.
*   **Inference Token (cToken):** The actual text tokens (word pieces) generated by the LLM during inference.
*   **Economic Relationship:** Users spend `iToken` to receive Inference Tokens, and hardware providers mint (earn) `iToken` by generating Inference Tokens.

---

### 2. Model Forgery Defense & Node Blacklisting (Gap 2 Resolved)
*   **The Threat:** Malicious nodes claiming to run premium models (e.g., 70B) while actually running cheap, low-parameter models (e.g., 7B) to pocket higher rewards.
*   **Resolution (Model Identity Proof + Optimistic Challenger):**
    1.  **Model Hash Registration:** Nodes register the SHA256 hash of their GGUF model files on the DHT/ledger.
    2.  **Staking and Slashing:** Nodes must stake `iToken` to accept queries.
    3.  **Optimistic Challenger Economics:** Active verification overhead is kept at 0% under normal operation. If a user suspects forgery or bad quality, they file a "Challenge" by staking a small amount of iToken. Only then does a validator node execute mathematical verification (VeriLLM). If cheating is proven, the node's staked iTokens are slashed (awarded to the challenger/validator) and the node is blacklisted.

---

### 3. Review Manipulation / Rating 어뷰징 Prevention (Gap 3 Resolved)
*   **The Threat:** Node operators creating Sybil accounts to upvote their own models or downvote competitors.
*   **Resolution (Stake-Weighted Feedback + Costly Voting):**
    *   Submitting a rating requires staking iTokens and paying a transaction fee, preventing infinite free 어뷰징.
    *   Ratings are aggregated using a **Stake-Weighted Median** (similar to Bittensor's Yuma Consensus), automatically clipping outlier votes.

---

### 4. Time Depreciation / Intelligence Deflation (Gap 4 Resolved)
*   **The Threat:** Legacy models keeping high reward weights permanently, ignoring newer, superior models.
*   **Resolution (Dynamic TQW Decay):**
    *   The Token Quality Weight ($TQW$) automatically decays over time relative to global benchmarks (e.g., MMLU-Pro) and declining user bidding volume. This ensures the market dynamically allocates higher value to cutting-edge models.

---

### 5. Provider Asset Portfolio Dashboard (Gap 5 Resolved)
*   To realize the vision of "my hardware is my asset," a **Provider Asset Portfolio** UI specification is added. It displays generated tokens, active TQW, and real-time iToken earnings per hardware unit.

## ⚡ Additional User Feedback Integration

### A. Decoupled Local LLM API Integration (Simple is Best)
*   **Old Plan:** Manually spawning and managing `llama-server` subprocesses from the daemon (complex).
*   **New Plan:** The iToken daemon acts as a **lightweight P2P Reverse Proxy**. It connects directly to existing local API engines (Ollama on `11434`, LM Studio on `1234`, Kobold.cpp on `5001`) via OpenAI-compatible endpoints (`/v1/chat/completions`).
*   **Zero Configuration:** Auto-scans local ports on startup to discover active models and publish them to the DHT. Manual IP/Port override (`http://192.168.0.5:12345`) is also fully supported.

### B. Energy-Saving "1 Query = 1 Node" Routing
*   **Old Plan:** Running redundant executions on 2+ nodes for every query (high power waste).
*   **New Plan (Optimistic Routing):** The default path routes **1 query to exactly 1 trusted node** based on Reputation and Staking. Since the Optimistic Challenger model handles post-inference fraud disputes, we eliminate redundant computing and save over 90% of energy.

### C. Speed (TPS) and Hardware (CPU vs. GPU) Valuation Formula
*   **Compensation Formula:**
    $$\text{iToken Reward} = \text{Generated Tokens} \times TQW_{M, Q} \times \text{Speed Multiplier}(TPS)$$
*   **Dynamic Speed Multiplier:** Calculated relative to the network's moving median speed for that model class:
    $$\text{Speed Multiplier}(TPS_{node}) = \left( \frac{TPS_{node}}{TPS_{network\_moving\_median}} \right)^\gamma$$
*   **Market Separation:** Fast GPU nodes handle real-time chat requests with minimum TPS thresholds. Slow CPU nodes automatically bid for cheap, asynchronous batch tasks (e.g., translation, batch summarization) where latency is not critical, optimizing global resource allocation.

## 🌐 Fusing Torrent (P2P Seeding) and Blockchain (e-coin)

iToken is the historical fusion of **BitTorrent's direct peer-to-peer data streaming** and **blockchain's persistent token value**.

1.  **Fixing Torrent's Free-Rider Problem:** By rewarding persistent hosting (seeding models) with real-time **iToken mining**, users have a direct financial incentive to keep their nodes online.
2.  **Fixing Blockchain's Useless Computation:** Instead of wasting electricity solving arbitrary mathematical puzzles, iToken nodes perform **useful LLM inference computation** to mint currency.
