## 🤝 핵심 합의 사항 & Gap 해결 방안 (5가지)

### 1. 용어 체계 확정 (Gap 1 해결)
*   **iToken (네이티브 화폐):** iToken 분산 장부상의 단일 주권 통화(Cryptocurrency)이자 자산 단위입니다.
*   **추론 토큰 (Inference Token):** LLM이 생성한 실질적인 텍스트 조각(텍스트 토큰)입니다.
*   **합의된 관계:** 사용자는 추론 토큰을 생성받는 대가로 `iToken`을 소모하고, 하드웨어 공급자는 추론 토큰을 제공하는 만큼 `iToken`을 채굴(Mint)합니다.

---

### 2. 모델 위조 및 사기 노드 퇴출 (Gap 2 해결)
*   **문제점:** 저품질 모델(예: 7B)을 구동하면서 고품질 모델(예: 70B)인 척 속여 부당하게 높은 iToken 보상을 챙기려는 사기 위험.
*   **해결책 (Model Identity Proof + 낙관적 챌린저):**
    1.  **모델 해시 등록:** 노드가 제공할 모델의 GGUF 파일 SHA256 해시를 분산 원장에 사전 등록합니다.
    2.  **담보(Staking) 및 슬래싱:** 노드는 반드시 `iToken`을 담보로 묶어야 일감을 수주할 수 있습니다.
    3.  **낙관적 챌린저 분쟁 해결:** 평소에는 검증 비용을 0%로 유지하다가, 사용자가 이상 결과(위조 의심)를 감지해 소량의 iToken을 걸고 이의(Challenge)를 제기하면 검증 노드가 수학적 검증(VeriLLM 등)을 실행합니다. 사기가 확인되면 해당 노드의 담보 iToken을 몰수해 신고자에게 포상하고 노드를 영구 퇴출합니다.

---

### 3. 피드백(평가) 시스템 조작 방지 (Gap 3 해결)
*   **문제점:** 자작 업보트를 하거나 경쟁 모델에 테러 다운보트를 하는 등 피드백 어뷰징 위험.
*   **해결책 (Stake-Weighted Feedback + 평판 시스템):**
    *   사용자가 모델에 보트를 남기려면 반드시 `iToken` 스테이킹 및 트랜잭션 비용을 부담하도록 설계하여 무한 생성 어뷰징을 막습니다.
    *   평가 결과는 Bittensor의 Yuma Consensus와 유사하게 **검증자들의 스테이크 가중 중앙값(Stake-Weighted Median)**으로 필터링되어 극단적인 조작표를 자동 클리핑합니다.

---

### 4. 시간에 따른 지능 감가상각 (Gap 4 해결)
*   **문제점:** 구식 모델의 평판과 가치 배율이 변하지 않고 영구 고착되는 문제.
*   **해결책 (지능 디플레이션 및 동적 TQW):**
    *   모델 품질 가중치($TQW$)에 시간 감쇠 계수를 도입하여, 구형 모델의 TQW는 새로운 평가나 글로벌 지능 벤치마크 지표의 하락에 따라 자동으로 우하향(Decay)합니다. 이를 통해 시장은 항상 최신 지능 모델에 더 높은 iToken 가치를 지불하게 됩니다.

---

### 5. 공급자 자산 포트폴리오 대시보드 (Gap 5 해결)
*   "내 하드웨어가 곧 나의 실질 자산"임을 직접 체감할 수 있도록, 노드 운영자가 보유한 하드웨어 스펙별 누적 생성 토큰 수, 실시간 TQW 배율, 24시간 수익 변동률을 한눈에 볼 수 있는 **Provider Asset Portfolio** UI 스펙을 구현 계획에 추가했습니다.

## ⚡ 추가 사용자 요청 사항 반영 완료

### A. 외부 로컬 추론 API 연동 (Simple is Best)
*   **기존 계획:** 데몬 내부에서 직접 C++ 기반 llama-server를 실행 및 통제하려고 하여 구현이 복잡했음.
*   **개선안:** 이미 사용자가 로컬 PC에 설치해 둔 **Ollama(11434 포트)나 LM Studio(1234 포트) 등 기존 도구의 OpenAI 호환 HTTP API를 iToken 데몬이 안전한 프록시로 토스하고 스트리밍하는 방식으로 전면 교체**했습니다.
*   **사용성:** 사용자는 LM Studio만 켜두면 iToken 데몬이 자동으로 스캔하여 P2P 네트워크에 연결합니다. 특정 IP/포트(`http://192.168.0.5:12345`)를 지정하는 것만으로 연동되는 수동 설정도 완벽 지원하여 범용성을 갖추었습니다.

### B. 에너지 절약을 위한 "1 Query = 1 Node" 기본 노선 확립
*   **기존 계획:** 합의 검증을 위해 매번 2개 이상의 노드가 동일 쿼리를 계산하여 전력과 컴퓨팅 자원이 크게 낭비되었음.
*   **개선안 (낙관적 라우팅):** 노드의 풍부한 담보(Stake)와 누적 평판을 바탕으로, 기본 경로에서는 **1개의 쿼리를 1개의 신뢰 노드에만 단독 라우팅**하여 답변을 즉시 스트리밍합니다. 사후에만 분쟁을 걸러내는 낙관적 챌린저 메커니즘이 뒷받침되기에 에너지를 90% 이상 절약하는 효율적 1:1 라우팅이 비로소 가능해집니다.

### C. 속도(TPS) 및 하드웨어(CPU vs GPU) 차등 보상 공식 수립
*   **정산 공식:** `iToken 보상 = 생성 토큰 수 × TQW × Speed Multiplier(TPS)`
*   **동적 속도 지수:** 고정된 값이 아닌, 네트워크의 실시간 **이동 중앙값 속도(Network Moving Median TPS)** 대비 해당 노드의 상대 속도 비율로 가중치($TPS_{node} / TPS_{median}$)를 계산합니다. 하드웨어가 발전해 평균 속도가 다 같이 빨라지면 가중치 기준도 자동으로 올라가므로 인플레이션을 방지합니다.
*   **용도별 자동 배분:** 실시간 채팅(고속 GPU 노드)과 비동기 배치 분석(저속 CPU 노드) 시장이 입찰가와 TPS 장벽에 의해 오더북상에서 유기적으로 나뉘어 효율적으로 작동합니다.

## 🌐 e-coin(iToken)과 토렌트(Torrent)의 기술적 융합

이 모델은 본질적으로 **토렌트의 실시간 분산 P2P 리소스 공유 아키텍처**와 **블록체인의 영구 자산 이코노미**를 결합한 혁신적인 형태입니다. 

1.  **토렌트의 한계(무임승차) 극복:** 다운로드 완료 후 배포(Seeding)를 중단하던 무임승차자들에게 **실시간 iToken 채굴 보상**을 제공함으로써, 사용자들이 LLM 모델을 계속 호스팅하고 네트워크를 유지할 강력한 동기를 제공합니다.
2.  **블록체인의 한계(무의미한 연산) 극복:** 쓸모없는 암호 퀴즈 해싱 계산 대신, 인류에게 실질적으로 기여하는 **AI 추론 연산(Compute)**을 블록체인의 작업 증명(PoW)으로 승화시킵니다.

> 모든 사전 문서는 본 합의 사항을 기준으로 동기화 완료되었으며, 이제 승인에 맞춰 실제 코드 개발 단계로 전개할 준비가 끝났습니다.
